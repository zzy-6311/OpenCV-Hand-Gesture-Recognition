# 右手五指状态识别：黑背景新版与旧白板版本

使用 OpenCV、手部掩膜和轮廓几何，判断右手拇指、食指、中指、无名指、小指的伸出 / 收起状态。

**当前推荐先运行 `python fpga_new/main.py`，查看最新黑背景固定裁剪版本。** 新版面向黑色固定背景板、右手掌朝向镜头、手从画面右侧进入的场景。它作为独立目录加入仓库，原有三个浅色背景板版本及其示例视频继续保留。

`fpga_new` 和 `fpga` 都是面向 FPGA 移植的 **Python/OpenCV 算法参考**，不是可直接烧录的 Verilog/VHDL 工程。本仓库没有包含本次黑背景版本的 RTL 综合或上板结果。

## 四个版本的用途

| 目录 | 背景与用途 | 主要特点 | 默认视频 |
| --- | --- | --- | --- |
| `fpga_new/` | **最新黑背景版本，当前优先使用和继续优化** | 320×180 输入，固定裁剪成 250×180，原生右侧进入，不旋转图像；简化前处理和低精度几何 | `data/black/test/` |
| `fpga/` | 旧浅色背景板的 FPGA 算法参考 | 默认 320×180，可选 640×360；固定 90° 坐标转正、ROI 坐标限制、白板及阴影处理 | `data/test/` |
| `win_end/` | 旧浅色背景板的电脑端简化视频运行版 | 长边最多 1280，实际裁剪白板并自动判断旋转；保留较完整浮点处理和旧识别兜底 | `data/test/` |
| `win_yuan/` | 旧浅色背景板的完整开发源码 | 照片、视频、摄像头入口，阶段调试、插件开关、照片评测及旧模板标定工具 | `data/test/` |

## 安装和快速运行

验证环境为 Windows、Python 3.11.9、NumPy 2.4.6、OpenCV 5.0.0、Pillow 12.3.0；依赖锁定在 `requirements.txt`。视频窗口需要桌面图形环境和带 GUI 的 `opencv-python`。

下载完整仓库后，在仓库根目录执行：

```powershell
python -m pip install -r requirements.txt

# 推荐：最新黑背景版本，默认播放 data/black/test/test1.mp4
python fpga_new/main.py

# 指定黑背景起始视频，也可以传入同类视频文件夹
python fpga_new/main.py data/black/test/test2.mp4
```

黑背景新版固定使用 320×180 输入，不提供 `--resolution` 切换。电脑入口接收 16:9 原图，一次缩放到 320×180 后实际裁剪；核心入口 `recognize_cropped` 直接接收 250×180、uint8 BGR 图像。输入需要符合固定背景板位置和右侧进手条件，不会自动定位或追踪背景板。

旧白板版本仍按原命令运行：

```powershell
# 旧电脑端简化视频版
python win_end/main.py
python win_end/main.py data/test/test2.mp4

# 旧 FPGA 参考版：默认 320×180，可选 640×360
python fpga/main.py
python fpga/main.py --resolution 640x360
python fpga/main.py data/test/test3.mp4 --resolution 320x180

# 旧完整开发版
python win_yuan/main.py video
python win_yuan/main.py video data/test/test2.mp4
```

默认素材路径按脚本位置解析，不依赖终端当前目录。`fpga_new`、`fpga`、`win_end` 手动传入的相对路径相对于终端当前目录；指定文件时会收集同目录视频并从该文件开始。`win_yuan` 还会尝试仓库目录和默认视频目录，因此可直接传入 `test2.mp4`。

## 视频显示和按键

显示完整输入画面，并将识别标记映射回原图。每帧计算并显示完成后才读取下一帧；计算较慢时慢放，不为追赶播放进度跳帧。默认循环当前视频，按键才更换视频。

让识别窗口获得焦点后，用英文输入法操作，字母键支持大小写：

| 按键 | 操作 |
| --- | --- |
| `N` / 右方向键 | 下一段视频 |
| `P` / 左方向键 | 上一段视频 |
| 空格 | 暂停 / 继续 |
| `R` | 从头重播当前视频 |
| `H` | 简洁 / 详细识别信息 |
| `Q` / `Esc` / 关闭窗口 | 退出 |

`N` 是下一段视频，不是下一帧。旧 `win_yuan` 还保留阶段查看和插件开关；它的视频模式下 `R` 用于重播，手动 ROI 使用 `O`。

## 最新黑背景版的流程与边界

`fpga_new` 当前代码更新于 **2026-10-21**：

1. 输入固定为 **320×180**；直接裁剪 `x=[40,290)`、`y=[0,180)`，核心只处理 **250×180**。这是实际裁剪，不是保存整图再用 ROI 标记限制。没有白板定位、动态图像旋转或 ROI 标记图。
2. 原生使用右侧进手坐标。仍测量掌心和手腕之间的方向，供点坐标和几何计算使用，**不旋转图片或掩膜**。旧腕部测量无效时，读取右侧进入截面的最长连续段中点作为参考。
3. 以灰度阈值 **40** 分离黑背景和前景，执行 **3×3 开运算、连通域清理、内部补洞**。不再执行旧白板定位、阴影颜色过滤或颜色掌心重建。补洞保留，因为手内暗纹仍会影响掌心和轮廓。
4. 掌心定位保留固定 **7×7 闭运算**；该临时结果只服务掌心测量，不直接覆盖手指识别轮廓。然后进行距离扫描、轮廓候选测量和五指身份/伸缩判断。
5. 侧向拇指使用已有根部位置、长度和宽度区分外伸拇指与蜷指关节，并允许末端内弯；没有按照片编号、视频帧号或正确答案写识别特例。
6. 距离状态为 **11 位 Q2**，仍保留 0.25 像素步长；归一化量保留到 1/32，弧长 Q4、根部横向位置 Q6。掌心与手指两次距离扫描依次复用同一工作区，工作区只属于当前帧，不依赖历史帧。
7. 补洞用三种状态复用清理后的掩膜，逻辑可用 2 位表达；仍采用固定四趟扫描。全前景等无法形成有效掌心半径的输入正常返回未识别，避免无穷哨兵引起异常。

固定裁剪把像素数从 57,600 降为 45,000，减少 **21.875%**。同尺寸有效距离图从 12 位降到 11 位，逻辑容量从 67,500 字节降到 61,875 字节，减少 **8.33%**。这些只描述对应像素和状态图的规模，不能直接当作整板资源下降比例：Python 的距离容器仍为 `uint16`，补洞容器仍为 `uint8`，两次距离扫描也仍然存在。

该核心仍包含连通域、多次整图扫描、轮廓访问及部分浮点几何，尚不是只用行缓存的单趟像素流水线。本次没有新的 RTL 综合，不能承诺硬件占用从 85% 降至 60%，也不能据电脑播放速度推算 FPGA 帧率。

## 黑背景照片复查（自行准备素材）

**300 张黑背景开发照片及真值表没有打包进发布仓库。** 随附三个黑背景视频，可直接试运行；需要照片复查时，自行准备符合输入条件的照片：

```powershell
# 显式指定照片目录或某张起始照片
python fpga_new/main.py --images C:/my-photos/black-hand

# 也可自行放入仓库 data/end 后运行
python fpga_new/main.py --images
```

省略 `--images` 的路径时，默认使用仓库 `data/end`；仓库未附此目录的照片，没有准备素材时会提示路径不存在。照片模式用 `N`/右箭头下一张、`P`/左箭头上一张、`H` 切换详情、`Q`/`Esc` 退出。

可在照片目录放入带表头的 UTF-8 `_真值.tsv`，字段为 `file`、`code`、`hand_present`、`confidence`，以制表符分隔。`file` 与照片名一致；`code` 按 `T I M R P` 顺序组合，分别表示拇指、食指、中指、无名指、小指；有手握拳时 `code` 留空、`hand_present=true`，无手时 `hand_present=false`。只有 `confidence=high` 才显示“正确/不正确”，没有标签仍可正常识别并显示“未标注”。

真值仅用于识别完成后的屏幕比对，不进入识别算法。统一数字命名如 `0001.png` 会按自然顺序显示编号，方便复查。

## 旧白板 `fpga` 参考版本状态（2026-10-17）

以下说明保留旧白板 `fpga` 的算法状态。本次新增黑背景 `fpga_new`，没有用新算法覆盖 `fpga`、`win_end` 或 `win_yuan`。

- 默认 **320×180**，可用 `--resolution 640x360` 切换。原始图片或视频帧只缩放一次到所选尺寸；后续各阶段都使用这个尺寸，没有在小尺寸模式下恢复高分辨率计算。非 16:9 输入等比缩放并补边。
- 使用 ROI 坐标限制有效区域，不把 ROI 裁成另一张可变尺寸的工作图；固定顺时针 90° 使用逻辑坐标，宽高对应变为 180×320 或 360×640。显示仍是完整原图叠加结果。
- 白板颜色和局部边缘统一处理，取消先尝试颜色、失败再执行 Canny 的第二条路线；直边使用有界整数斜率投票。
- 阴影统一根据本帧背景、掌心颜色及邻近皮肤支持过滤，覆盖与手相连的阴影；不能保证任意光照下均无误判。
- 只需判断是否达到 8 像素厚度的位置，改用与既有距离规则等价的固定二值窗口。其他需要距离的阶段保留完整距离计算，直接使用整数码，减少整帧浮点副本。
- 距离计算仍为 **2 位二进制小数、12 位逻辑状态**，Python 容器为 `uint16`；轮廓坐标取整，归一化量保留到 **1/32**，局部指尖弧长保留 **4 位二进制小数**，手指横向位置保留 **6 位二进制小数**。
- 颜色中位数使用 256 桶整数直方图；裁小臂直接判断直线两侧；填孔使用固定四次扫描。固定扫描对复杂蛇形背景不严格等价，现有素材已回归。
- 保留普通指尖测量、弯曲指关节支撑和五指身份分配；停用整圈轮廓重采样及三条曲率/拇指补救。旧角度模板兜底仍不使用。已经删除不再调用的辅助函数及常量；判断失败时显示“无法可靠判断”。

这些调整减少重复扫描、中间数据和部分处理路线，但**整套算法仍有整帧统计、连通域、双向距离扫描、随机轮廓访问及部分浮点几何计算**，尚不是完全无帧缓存的单遍像素流水。320 的像素数是 640 的四分之一，不代表整机资源或 DDR 流量必然减少 75%。Python 的数值容器也不能直接当作 RTL 寄存器位宽。

该版本要求右手从画面右侧伸入、手位于背景板前。倒向手、其他进手方向应使用 PC 版本对照，或另行验证算法适配。

## 旧版硬件研究记录与新版资源结论

**下列数字属于 2026-10-17 的旧白板核心候选，不是本次黑背景 `fpga_new` 的资源报告，也不能直接套用到它。** 黑背景新版尚未进行新的 RTL 综合，不能由 Python 改动承诺整板占用从 85% 降到 60%。

另行开发的完整核心 RTL 候选尚未随本仓库发布。2026-10-17 的 C5 候选以 320×180 为主，已完成 C 模型检查和 Vitis HLS 2020.2 综合；**完整 RTL 仿真、Vivado 完整核心资源及布局布线时序尚未验收，验证目前暂停**。

以 Xilinx Artix-7 `xc7a35t-cpg236-1` 为代理器件，HLS 报告估计完整核心为 **156904 LUT、101205 FF、171 个 BRAM18、79 个 DSP**；估计时钟周期 **34.101 ns**，未达到设定的 10 ns 目标。该报告的完整帧周期和启动间隔未知，因此不能给出可信的实时帧率。以上不包含摄像头、显示、外部输入帧存及 DDR 适配，也不是安路器件实际占用或上板频率。

当前估值已经明显超出该代理器件的 LUT、FF 和片上存储容量，不能当作可直接部署版本。安路 LUT4、DSP、ERAM 与 Xilinx 资源不能按个数等价换算；目标板是否能容纳优化后的核心，需要在明确硬件结构及存储接口后继续验证。

## 旧白板完整开发版的可选工具

以下工具只属于 `win_yuan`。视频试用无需这些工具；照片开发需要自行准备适合旧白板流程的图片和真值。仓库随附的视频不能代替照片评测素材。

```powershell
# 观察自备开发照片：放入 data/new
python win_yuan/main.py image new

# 摄像头开发入口
python win_yuan/main.py camera

# 查看照片评测参数
python win_yuan/regression.py --help

# 自备 data/new 图片与 _真值.tsv 后执行
python win_yuan/regression.py new --json current.json

# 查看旧模板标定工具参数
python win_yuan/calibrate_template.py --help
```

旧版评测工具的真值文件为 UTF-8 TSV：第一列是图片文件名，第二列是伸出手指的字母组合，顺序为 `T I M R P`（拇指、食指、中指、无名指、小指）；空组合表示握拳。真值只供评测或明确执行的标定使用，不作为正常识别输入。

照片评测与标定的相对报告路径位于仓库 `reports/`，生成内容不进入 Git。`all` 评测还需要原有旧照片、非标准照片及相应真值；未准备素材时应按提示补齐，不应把缺失样本当作识别成功。

`calibrate_template.py` 针对开发版保留的旧角度模板；默认只生成标定报告，只有显式传入 `--write` 才会写回 `win_yuan/plugins.py`。它不会更新 `fpga` 或 `fpga_new` 的低精度几何算法。该工具禁止用 `data/test` 做模板标定；新的 `data/black/test` 也只用于独立验证，不应作为开发或标定素材。

# 右手五指状态识别（OpenCV）

从图像、视频或摄像头画面中识别右手五根手指各自的伸开 / 收起状态，作为后续机械手控制的视觉输入。当前优先在背景变化较小、手掌朝向镜头的条件下完成手指识别，同时为将来移植 FPGA 保留可分离的算法模块。

输出顺序固定为 `[T, I, M, R, P]`，即 `[拇指, 食指, 中指, 无名指, 小指]`。例如 `[False, True, True, False, False]` 表示仅食指和中指伸开。识别结果位于 `state.flags["recognize"]["finger_states"]`；`recognize` 不存在或为 `None` 表示未取得识别结果，不能当成握拳。

使用传统图像处理，不使用深度学习、MediaPipe、OpenCV contrib 或背景差分。默认不镜像。当前仓库实现视觉识别与显示，尚未实现机械手通信和 FPGA 硬件逻辑。

## 运行需要哪些文件

仓库只有三个 Python 文件，全部直接放在根目录：

| 文件 | 用途 |
| --- | --- |
| `main.py` | 输入、插件调度、显示和按键 |
| `plugins.py` | 分割、掌部几何、候选检测、状态保持和绘制 |
| `finger_geometry.py` | 手指身份与伸缩识别 |

调用关系为 `main.py → plugins.py → finger_geometry.py`。三个文件一起复制即可保留完整的程序代码；图片和视频模式还需要相应素材。开发用的评估、测试、标定和导出工具保留在开发目录，不是这份仓库的运行依赖。

## 安装与启动

本次验证环境：Windows、Python 3.11.9、NumPy 2.4.6、opencv-python 5.0.0.93、Pillow 12.3.0。Pillow 用于中文绘制；Windows 下优先使用系统中文字体。依赖版本保存在根目录的 `requirements.txt`。

在仓库根目录执行：

```powershell
python -m pip install -r requirements.txt
python -B main.py image camera
```

需要带窗口支持的 `opencv-python`；主程序通过 OpenCV 窗口显示图像，不能仅安装 headless 版本。`-B` 用于避免运行时生成 Python 字节码缓存，不影响识别。

| 命令 | 输入 |
| --- | --- |
| `python -B main.py` | 当前默认：29 张 FPGA 摄像头标准照片 |
| `python -B main.py image camera` | `data/new_camera/shot_01.png` 至 `shot_29.png` |
| `python -B main.py image old` | `data/` 下的旧照片与补充图 |
| `python -B main.py video 1` | `data/gesture_video_1.mp4` |
| `python -B main.py video 2` | `data/gesture_video_2.mp4` |
| `python -B main.py camera` | 实时摄像头，默认设备索引为 0 |

自定义视频可用 `python -B main.py video "D:\videos\hand.mp4"`；相对视频名从 `VIDEO_DATA_DIR` 读取，默认是 `data/`。摄像头索引可在 `main.py` 的 `CAMERA_INDEX` 中修改。

图片模式不会自动翻页，用 `n` / `p` 切换；视频默认循环。标准照片默认关闭 ROI 限制，旧照片和视频默认开启，可按 `r` 切换。

真值 TSV 文件仅供开发评估使用，格式为“文件名 + TAB + 伸开的手指字母”，允许空状态表示握拳。主程序不读取真值进行识别。

### 按键与显示

| 按键 | 功能 |
| --- | --- |
| `q` / `Esc` | 退出 |
| 空格 | 暂停 / 继续 |
| `1` / `2` / `3` | 原图 / 初始掩膜 / 清理后掩膜 |
| `4` / `5` / `6` | 掌心重建 / 掩膜上识别 / 原图上识别（默认） |
| `r` / `m` | ROI 限制 / 手动镜像开关 |
| `d` / `f` / `l` | 信息叠加 / 全屏 / 控制台列出插件 |
| `n` / `p` / `R` | 图片模式：下一张 / 上一张 / 重新读取 |

五个状态方块的显示顺序为 `P R M I T`，与程序输出数组 `T I M R P` 的顺序相反。实心绿色表示伸开，空心灰色表示收起；过渡帧可能保持上一次稳定结果。`held=True` 表示正在保持旧状态，`settled` 表示稳定性门控结果。

## 当前算法

处理顺序为：输入缩放和转正 → 颜色阈值分割 → 掩膜清理 → 掌心重建 → 指尖与指缝候选 → 手指身份和伸缩判断 → 稳定性门控 → 绘制。

默认 `plugins.FINGER_IDENTITY_MODE = "geometry"`。几何方法沿候选指尖两侧轮廓采样，用中点估计局部指轴，再将指轴投影到掌部参考线，得到归一化横向位置。该投影是身份判定特征，并非检测到的真实关节点。

拇指单独判定，其余四指按食指、中指、无名指、小指的顺序进行一对一分配。身份与伸缩状态分别判断：短粗候选可以占据某根手指的位置，同时输出收起。几何测量不可用时回退到旧方法，并在匹配信息中记录原因。旧方法仍可通过 `FINGER_IDENTITY_MODE = "legacy"` 启用。

主要参数位置：

| 位置 | 参数用途 |
| --- | --- |
| `main.py` | 输入源、图片和视频目录、摄像头索引、分辨率上限、显示 |
| `plugins.py` | 颜色分割、ROI、重建、候选检测、算法模式、稳定性门控 |
| `finger_geometry.py` 的 `GeometryConfig` | 局部几何测量、短粗候选阈值、Q10 手指位置参考 |

## 2026-10-09 改动

- 接入局部指轴和掌部横向位置识别，将手指身份与伸缩判断分开，保留旧方法作为回退和对照。
- 修复旧方法角度偏移搜索的缩进错误，以及探测角度未使用拟合角度缩放的问题。
- 修复边界采样将图像边缘重复当成前景的问题。
- 调整绘制顺序，使画面显示稳定性门控之后的实际输出；关闭 ROI 时，运动检测使用整帧。
- 将视频素材路径与照片批次分离，避免选中 `new_camera` 后找错视频目录。
- 开发目录保留独立静态评估、算法对照、测试和定点分配参考向量；运行仓库简化为根目录三个 Python 文件。

## 验证与当前结果

静态评估逐张重置运行状态，关闭绘制和时序保持；五位状态全部正确才计为正确。缺失或无法读取的有标签样本仍保留在分母中，未识别到手与握拳区分处理。

| 素材组 | 五位状态完全正确 | 准确率 |
| --- | --- | --- |
| 标准 FPGA 摄像头照片 | 28 / 29 | 96.6% |
| 旧照片，包含手背朝镜头的 3 张 | 25 / 28 | 89.3% |
| 非标准照片 | 6 / 10 | 60.0% |
| 无真值诊断图 | 3 张 | 不计准确率 |

这些是开发使用的现有素材上的结果，参数也在这批素材上调整过，尚不能代表独立新拍素材的准确率。当前静态评估不能替代实时视频评估。

原开发版本通过 22 项测试。简化后的三个运行文件使用开发目录的工具单独检查：8 项几何算法测试通过，70 张素材预测与简化前一致，4 个图片 / 视频入口各处理并绘制 12 帧。

入口检查实际执行图像处理与绘制，但用测试替身接收窗口输出；它不验证真实窗口交互、实体摄像头连接或视频逐帧识别准确率。测试脚本和报告留在开发项目的 `codex/` 下，运行仓库不包含这些辅助文件。日常检查可直接使用上面的图片和视频启动命令。

### 尚未解决的问题

- `shot_08`：将 `IMR` 识别为 `IMP`，无名指与小指仍有混淆。
- `gesture_33` 系列三张手背照片仍错误；当前主要适用右手掌心朝向镜头。
- `nonstd_03/06/08/09` 仍错误，涉及遮挡、多余候选和几何位置偏移。
- 掩膜分割、候选检测和掌部坐标仍会影响后续身份判断；严重重叠或分割损坏不能靠身份分配单独修复。
- 视频尚无逐帧真值，本轮不提供实时准确率或固定帧率承诺。

## FPGA 移植边界

`finger_geometry.py` 中的 `assign_slots_q10` 使用最多 4 个非拇指候选、Q10 坐标和 Q20 平方差代价。输入范围受限，默认参数下代价可容纳于有符号 32 位整数。四指状态空间为 16 个子集，分配时仅枚举与候选数量相符的子集。

局部几何测量及上游 OpenCV 操作仍包含浮点运算、插值、平方根、距离变换和轮廓追踪。目前完成的是软件参考实现，尚未完成 RTL / HLS 实现、资源估计和时序验证。

开发目录另存有整数分配接口说明及 21 组参考向量，用于将来验证定点实现一致性；它们不参与主程序运行。

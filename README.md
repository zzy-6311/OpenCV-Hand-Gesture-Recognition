# 右手五指状态识别：PC 开发、视频运行与 FPGA 算法参考

使用 OpenCV、手部掩膜和轮廓几何，判断右手拇指、食指、中指、无名指、小指的伸出 / 收起状态。适用条件是背景变化较小、浅色矩形背景板、手掌朝向镜头。

仓库按用途分成三个独立版本。**普通电脑查看视频效果，先运行 `win_end/main.py`；继续研究 FPGA 移植，运行 `fpga/main.py`；修改完整开发流程，使用 `win_yuan/main.py`。** 根目录只放统一说明、依赖和共享素材。

## 三个目录分别是什么

| 目录 | 性质与用途 | 主要特点 |
| --- | --- | --- |
| `fpga/` | **面向 FPGA 移植的 Python 算法参考版本**，用于验证简化流程和低精度计算的识别影响 | 固定 640×360 输入、固定顺时针 90°、ROI 坐标限制、较低数值精度；要求手从画面右侧伸入；保留原图显示与视频播放控制 |
| `win_end/` | **电脑端简化视频运行版本**，适合直接播放视频、查看结果和做软件对照 | 单帧依次读取、计算、显示；长边最多 1280，实际裁剪白板并自动判断旋转角度；保留较完整的浮点计算和旧识别兜底 |
| `win_yuan/` | **电脑端完整开发源码**，用于开发、调试、观察处理阶段和照片回归 | 保留照片、视频、摄像头入口、插件注册、阶段查看与开关；附带照片评测及旧模板标定工具 |

三个版本面向不同目标，识别结果不保证逐帧一致。`fpga` 这个目录名表示优化方向：**里面仍是 Python/OpenCV 代码，不是 Verilog/VHDL 工程，也不能直接烧录到开发板。** 目前仍有浮点插值、开方和除法，尚未完成完整定点 RTL 实现或目标板资源验证。

## 安装和快速运行

本次验证环境：Windows、Python 3.11.9、NumPy 2.4.6、OpenCV 5.0.0、Pillow 12.3.0。依赖版本已写入 `requirements.txt`。视频窗口需要桌面图形环境和带 GUI 的 `opencv-python`。

下载完整仓库后，在仓库根目录执行：

```powershell
python -m pip install -r requirements.txt

# 电脑端视频运行版
python win_end/main.py

# FPGA 算法参考版
python fpga/main.py

# 完整开发版的视频入口
python win_yuan/main.py video
```

三个入口默认共用仓库内的 `data/test`，从 `test1.mp4` 开始，播放结束后重复当前视频。素材均为仓库中的真实文件，不依赖开发电脑路径、目录链接或仓库外的 `codex` 模块。

指定起始视频：

```powershell
python win_end/main.py data/test/test2.mp4
python fpga/main.py data/test/test3.mp4
python win_yuan/main.py video data/test/test2.mp4
```

`fpga` 和 `win_end` 也可接收自己的视频文件夹。指定单个文件时，会把同目录视频加入列表，并从指定文件开始。默认素材路径按照脚本位置解析，不依赖终端当前目录；这两个版本手动传入的相对路径相对于终端当前目录。`win_yuan` 还会尝试仓库目录和默认视频目录，因此可直接传入 `test2.mp4`。

## 视频显示和按键

显示完整输入画面，并将识别标记映射回原图。内部裁剪或转正不会直接作为显示背景。每帧计算并显示完成后才读取下一帧；计算较慢时慢放，不为追赶播放进度跳帧。

让识别窗口获得焦点后，用英文输入法操作：

| 按键 | 操作 |
| --- | --- |
| `N` / 右方向键 | 下一段视频 |
| `P` / 左方向键 | 上一段视频 |
| 空格 | 暂停 / 继续 |
| `R` | 从头重播当前视频 |
| `H` | 简洁 / 详细识别信息 |
| `Q` / `Esc` / 关闭窗口 | 退出 |

字母键支持大小写。默认循环当前视频，只有切换按键才更换视频。`N` 是下一段视频，不是下一帧。开发版还保留阶段查看和插件开关；视频模式下 `R` 始终用于重播，手动 ROI 使用 `O`。

## FPGA 参考版本当前状态

截至 2026-10-16，`fpga` 采用视频精度回退后验证的组合：

- 内部固定为 **640×360**；非 16:9 输入等比缩放并补边，固定顺时针 90° 后逻辑尺寸为 **360×640**。
- 白板用于计算有效区域，后续按坐标限制处理；显示仍使用完整原图。
- 距离计算使用 **2 位二进制小数、12 位逻辑状态**；Python 参考容器仍为 `uint16`。
- 轮廓坐标取整，归一化量保留到 **1/32**，局部指尖弧长保留 **4 位二进制小数**，手指横向位置保留 **6 位二进制小数**。
- 删除旧的角度模板手指身份兜底，保留主几何识别与曲率补充；判断失败时显示“无法可靠判断”。

这里的低精度是经过识别回归的数值方案，移植时需要把寄存器、算术器和存储接口实际按对应位宽实现。12 位距离状态相对 16 位的理论位容量少 25%，**不代表整机资源减少 25%**。固定转置也仍有缓存和读写调度需求；目前不能保证目标 FPGA 资源足够或达到指定帧率。

该版本要求右手从画面右侧伸入、手位于背景板前。倒向手、其他进手方向应使用 PC 版本对照，或另行验证算法适配。

## 已有验证与识别限制

下表只对应当前 `fpga` 数值组合，以五根手指的身份和状态全部匹配为正确。结果来自参与开发和优化选择的已有素材，不能当作新人物、新场景的独立测试准确率。

| 素材 | 正确数 / 总数 | 说明 |
| --- | --- | --- |
| 正常方向标准照片 | **236 / 250（94.4%）** | 相对本轮简化前的 242/250，下降 2.4 个百分点 |
| 全部标准照片 | 236 / 253 | 另含 3 张不符合固定进手方向的倒向照片 |
| 非标准照片 | 18 / 22 | 遮挡、并拢等情况仍不能保证 |
| 主要视频标注帧 | **83 / 91** | 来自 `test3` 第 500～600 帧中的清晰标注部分 |
| 额外困难视频帧 | 18 / 23 | 三个视频中原先涉及旧兜底的定向样本 |
| 合并视频标注帧 | **101 / 114** | 上述两组无重叠；与简化前基线的正确总数相同 |
| 无手、空板帧 | 67 / 67 | 当前选取的空场样本未误报手 |

正确总数持平不代表每一帧都没有变化。三个运动模糊困难帧由原来 2 个正确变为 1 个；合并 114 帧中仍存在新增错误和恢复正确的情况。

当前 `fpga` 代码已完成 433 输入回归，以及三个视频共 1651 帧的完整运行检查，无运行异常。**三个视频尚未全部逐帧标注，因此没有整段视频准确率。** `win_end`、`win_yuan` 本次进行发布入口、依赖与抽样对照验证，不将此表的准确率套用到它们。

并拢、严重重叠、手背、左手、运动模糊、光照变化或白板定位失败都可能导致误判。识别到某种状态不表示算法恢复了被遮挡手指的完整轮廓。项目目前输出软件识别结果，尚未包含 FPGA 硬件工程或机械手通信。

## 完整开发版的可选工具

视频试用无需以下工具。照片开发需要自行准备图片和真值；仓库自带的三个 MP4 不能代替照片评测素材。

```powershell
# 观察自备开发照片：放入 data/new
python win_yuan/main.py image new

# 摄像头开发入口
python win_yuan/main.py camera

# 查看照片评测参数
python win_yuan/regression.py --help

# 自备 data/new 图片与 _真值.tsv 后执行
python win_yuan/regression.py new --json current.json

# 查看旧模板标定工具参数
python win_yuan/calibrate_template.py --help
```

真值文件为 UTF-8 TSV：第一列是图片文件名，第二列是伸出手指的字母组合，顺序为 `T I M R P`（拇指、食指、中指、无名指、小指）；空组合表示握拳。真值只供评测或明确执行的标定使用，不作为正常识别输入。

照片评测与标定的相对报告路径位于仓库 `reports/`，生成内容不进入 Git。`all` 评测还需要原有旧照片、非标准照片及相应真值；未准备素材时应按提示补齐，不应把缺失样本当作识别成功。

`calibrate_template.py` 针对开发版保留的旧角度模板；默认只生成标定报告，只有显式传入 `--write` 才会写回 `win_yuan/plugins.py`。它不会更新 `fpga` 的低精度几何算法。该工具禁止用 `data/test` 做模板标定，开发与独立验证素材应分开准备。

# 右手五指状态识别：PC 开发、视频运行与 FPGA 算法参考

使用 OpenCV、手部掩膜和轮廓几何，判断右手拇指、食指、中指、无名指、小指的伸出 / 收起状态。适用条件是背景变化较小、浅色矩形背景板、手掌朝向镜头。

仓库按用途分成三个独立版本。**普通电脑查看视频效果，先运行 `win_end/main.py`；继续研究 FPGA 移植，运行 `fpga/main.py`；修改完整开发流程，使用 `win_yuan/main.py`。** 根目录只放统一说明、依赖和共享素材。

## 三个目录分别是什么

| 目录 | 性质与用途 | 主要特点 |
| --- | --- | --- |
| `fpga/` | **面向 FPGA 移植的 Python 算法参考版本**，用于验证简化流程和低精度计算的识别影响 | 默认 320×180，可选 640×360；固定顺时针 90°、ROI 坐标限制、较低数值精度、统一白板与阴影处理；要求手从画面右侧伸入 |
| `win_end/` | **电脑端简化视频运行版本**，适合直接播放视频、查看结果和做软件对照 | 单帧依次读取、计算、显示；长边最多 1280，实际裁剪白板并自动判断旋转角度；保留较完整的浮点计算和旧识别兜底 |
| `win_yuan/` | **电脑端完整开发源码**，用于开发、调试、观察处理阶段和照片回归 | 保留照片、视频、摄像头入口、插件注册、阶段查看与开关；附带照片评测及旧模板标定工具 |

三个版本面向不同目标，识别结果不保证逐帧一致。`fpga` 这个目录名表示优化方向：**里面仍是 Python/OpenCV 代码，不是 Verilog/VHDL 工程，也不能直接烧录到开发板。** 目前仍有浮点插值、开方和除法，尚未完成完整定点 RTL 实现或目标板资源验证。

## 安装和快速运行

本次验证环境：Windows、Python 3.11.9、NumPy 2.4.6、OpenCV 5.0.0、Pillow 12.3.0。依赖版本已写入 `requirements.txt`。视频窗口需要桌面图形环境和带 GUI 的 `opencv-python`。

下载完整仓库后，在仓库根目录执行：

```powershell
python -m pip install -r requirements.txt

# 电脑端视频运行版
python win_end/main.py

# FPGA 算法参考版：默认整条识别流程为 320×180
python fpga/main.py

# 可选 640×360，使用同一套识别流程
python fpga/main.py --resolution 640x360

# 完整开发版的视频入口
python win_yuan/main.py video
```

三个入口默认共用仓库内的 `data/test`，从 `test1.mp4` 开始，播放结束后重复当前视频。素材均为仓库中的真实文件，不依赖开发电脑路径、目录链接或仓库外的 `codex` 模块。

指定起始视频：

```powershell
python win_end/main.py data/test/test2.mp4
python fpga/main.py data/test/test3.mp4 --resolution 320x180
python win_yuan/main.py video data/test/test2.mp4
```

`fpga` 和 `win_end` 也可接收自己的视频文件夹。指定单个文件时，会把同目录视频加入列表，并从指定文件开始。默认素材路径按照脚本位置解析，不依赖终端当前目录；这两个版本手动传入的相对路径相对于终端当前目录。`win_yuan` 还会尝试仓库目录和默认视频目录，因此可直接传入 `test2.mp4`。

## 视频显示和按键

显示完整输入画面，并将识别标记映射回原图。内部裁剪或转正不会直接作为显示背景。每帧计算并显示完成后才读取下一帧；计算较慢时慢放，不为追赶播放进度跳帧。

让识别窗口获得焦点后，用英文输入法操作：

| 按键 | 操作 |
| --- | --- |
| `N` / 右方向键 | 下一段视频 |
| `P` / 左方向键 | 上一段视频 |
| 空格 | 暂停 / 继续 |
| `R` | 从头重播当前视频 |
| `H` | 简洁 / 详细识别信息 |
| `Q` / `Esc` / 关闭窗口 | 退出 |

字母键支持大小写。默认循环当前视频，只有切换按键才更换视频。`N` 是下一段视频，不是下一帧。开发版还保留阶段查看和插件开关；视频模式下 `R` 始终用于重播，手动 ROI 使用 `O`。

## FPGA 参考版本当前状态

截至 2026-10-17，本次更新 `fpga` 三个 Python 文件及本说明，两个 PC 版本继续保留原有算法与独立运行结构。

- 默认 **320×180**，可用 `--resolution 640x360` 切换。原始图片或视频帧只缩放一次到所选尺寸；后续各阶段都使用这个尺寸，没有在小尺寸模式下恢复高分辨率计算。非 16:9 输入等比缩放并补边。
- 使用 ROI 坐标限制有效区域，不把 ROI 裁成另一张可变尺寸的工作图；固定顺时针 90° 使用逻辑坐标，宽高对应变为 180×320 或 360×640。显示仍是完整原图叠加结果。
- 白板颜色和局部边缘统一处理，取消先尝试颜色、失败再执行 Canny 的第二条路线；直边使用有界整数斜率投票。
- 阴影统一根据本帧背景、掌心颜色及邻近皮肤支持过滤，覆盖与手相连的阴影；不能保证任意光照下均无误判。
- 只需判断是否达到 8 像素厚度的位置，改用与既有距离规则等价的固定二值窗口。其他需要距离的阶段保留完整距离计算，直接使用整数码，减少整帧浮点副本。
- 距离计算仍为 **2 位二进制小数、12 位逻辑状态**，Python 容器为 `uint16`；轮廓坐标取整，归一化量保留到 **1/32**，局部指尖弧长保留 **4 位二进制小数**，手指横向位置保留 **6 位二进制小数**。
- 颜色中位数使用 256 桶整数直方图；裁小臂直接判断直线两侧；填孔使用固定四次扫描。固定扫描对复杂蛇形背景不严格等价，现有素材已回归。
- 保留普通指尖测量、弯曲指关节支撑和五指身份分配；停用整圈轮廓重采样及三条曲率/拇指补救。旧角度模板兜底仍不使用。已经删除不再调用的辅助函数及常量；判断失败时显示“无法可靠判断”。

这些调整减少重复扫描、中间数据和部分处理路线，但**整套算法仍有整帧统计、连通域、双向距离扫描、随机轮廓访问及部分浮点几何计算**，尚不是完全无帧缓存的单遍像素流水。320 的像素数是 640 的四分之一，不代表整机资源或 DDR 流量必然减少 75%。Python 的数值容器也不能直接当作 RTL 寄存器位宽。

该版本要求右手从画面右侧伸入、手位于背景板前。倒向手、其他进手方向应使用 PC 版本对照，或另行验证算法适配。

## 已有验证与识别限制

下表对应当前发布的 `fpga` 代码，输入口径是原始媒体一次缩放到目标尺寸，以五根手指的身份和状态全部匹配为正确。结果来自参与开发和优化选择的已有素材，不能当作新人物、新场景的独立测试准确率。

| 素材 | 默认 320×180 | 可选 640×360 |
| --- | --- | --- |
| 正常方向标准照片 | **230 / 250（92.0%）** | **229 / 250（91.6%）** |
| 全部标准照片，另含 3 张倒向照片 | 230 / 253 | 229 / 253 |
| 非标准照片 | 16 / 22 | 18 / 22 |
| 全部照片 | 246 / 275 | 247 / 275 |
| 主要视频标注帧 | 81 / 91 | 85 / 91 |
| 额外困难视频帧 | 19 / 23 | 19 / 23 |
| 合并有手视频标注帧 | **100 / 114（87.7%）** | **104 / 114（91.2%）** |
| 无手、空板帧 | 67 / 67 | 67 / 67 |

停用曲率补救的单项对比中，正常标准照片 320 从 232/250 变为 230/250，640 从 232/250 变为 229/250；标注手势视频正确总数不变，但两档都各有一帧新增错和一帧恢复。这是该项取舍前后的比较，不是与最初版本的整体比较。

两档都已完成三个视频共 1651 帧的完整运行检查。随后清除未调用函数时，两档各 456 项回归、合计 912 项的识别数据与清理前完全一致，简洁/详细显示抽查也一致。**三个视频尚未全部逐帧标注，因此没有整段视频准确率。** 两种尺寸并不保证每一帧结果相同，也不能用输出一致率代替准确率。此表不适用于 `win_end`、`win_yuan`。

并拢、严重重叠、手背、左手、运动模糊、光照变化或白板定位失败都可能导致误判。识别到某种状态不表示算法恢复了被遮挡手指的完整轮廓。项目目前输出软件识别结果，尚未包含 FPGA 硬件工程或机械手通信。

## 当前硬件验证进度

另行开发的完整核心 RTL 候选尚未随本仓库发布。2026-10-17 的最新 C5 候选以 320×180 为主，已完成 C 模型检查和 Vitis HLS 2020.2 综合；**完整 RTL 仿真、Vivado 完整核心资源及布局布线时序尚未验收，验证目前暂停**。

以 Xilinx Artix-7 `xc7a35t-cpg236-1` 为代理器件，HLS 报告估计完整核心为 **156904 LUT、101205 FF、171 个 BRAM18、79 个 DSP**；估计时钟周期 **34.101 ns**，未达到设定的 10 ns 目标。该报告的完整帧周期和启动间隔未知，因此不能给出可信的实时帧率。以上不包含摄像头、显示、外部输入帧存及 DDR 适配，也不是安路器件实际占用或上板频率。

当前估值已经明显超出该代理器件的 LUT、FF 和片上存储容量，不能当作可直接部署版本。安路 LUT4、DSP、ERAM 与 Xilinx 资源不能按个数等价换算；目标板是否能容纳优化后的核心，需要在明确硬件结构及存储接口后继续验证。

## 完整开发版的可选工具

视频试用无需以下工具。照片开发需要自行准备图片和真值；仓库自带的三个 MP4 不能代替照片评测素材。

```powershell
# 观察自备开发照片：放入 data/new
python win_yuan/main.py image new

# 摄像头开发入口
python win_yuan/main.py camera

# 查看照片评测参数
python win_yuan/regression.py --help

# 自备 data/new 图片与 _真值.tsv 后执行
python win_yuan/regression.py new --json current.json

# 查看旧模板标定工具参数
python win_yuan/calibrate_template.py --help
```

真值文件为 UTF-8 TSV：第一列是图片文件名，第二列是伸出手指的字母组合，顺序为 `T I M R P`（拇指、食指、中指、无名指、小指）；空组合表示握拳。真值只供评测或明确执行的标定使用，不作为正常识别输入。

照片评测与标定的相对报告路径位于仓库 `reports/`，生成内容不进入 Git。`all` 评测还需要原有旧照片、非标准照片及相应真值；未准备素材时应按提示补齐，不应把缺失样本当作识别成功。

`calibrate_template.py` 针对开发版保留的旧角度模板；默认只生成标定报告，只有显式传入 `--write` 才会写回 `win_yuan/plugins.py`。它不会更新 `fpga` 的低精度几何算法。该工具禁止用 `data/test` 做模板标定，开发与独立验证素材应分开准备。

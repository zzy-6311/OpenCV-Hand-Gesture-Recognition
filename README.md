# 右手五指状态识别（OpenCV 视频版）

识别右手拇指、食指、中指、无名指、小指的伸开 / 收起状态。当前使用传统图像处理和轮廓几何，不依赖深度学习或 MediaPipe。适用条件是背景变化较小、浅色矩形背景板、右手掌心大致朝向镜头。

**仓库根目录是部署使用的优化版本，直接运行根目录的 `main.py`。** 程序固定执行“读取一帧 → 识别 → 在原图上显示结果 → 读取下一帧”，默认重复播放当前视频，按键才切换视频。

`old/` 保留带开发功能的最新源码，用于开发、调试和对照；其中的识别修复与根目录同步，目录名不代表旧算法。原来的 `end/` 已取消，优化版本已提升到根目录。

## 安装与运行

已验证环境：Windows、Python 3.11.9。需要桌面图形环境及带窗口功能的 `opencv-python`，不能只安装 headless 版本。

下载完整仓库后，在仓库根目录执行：

```powershell
python -m pip install -r requirements.txt
python main.py
```

默认从仓库自带的 `data/test/test1.mp4` 开始，播放结束后从头重复当前视频。无需准备额外素材，也不需要开发项目或 `codex` 目录。

可以指定起始视频或自己的视频文件夹：

```powershell
python main.py data/test/test2.mp4
python main.py "D:/my-videos"
python main.py "D:/my-videos/gesture.mp4"
```

指定文件时，以该文件作为起点，并将同文件夹中的视频加入可切换列表；指定文件夹时，从自然排序后的第一段开始。视频列表首尾循环。支持 `.mp4`、`.avi`、`.mov`、`.mkv`、`.m4v`、`.wmv`、`.webm`、`.mts`，具体能否解码取决于 OpenCV 的视频后端。

不带参数时，素材路径根据 `main.py` 所在目录确定，与终端当前工作目录无关。自行传入相对路径时，该路径相对于终端当前目录。

需要开发版功能时，可在仓库根目录运行以下命令。两版本共用仓库内的三个视频：

```powershell
python old/main.py video
python old/main.py video data/test/test3.mp4
```

## 显示与操作

窗口显示原始画面、中文手指识别结果和轮廓标记。内部裁剪、转正产生的标记会映射回原图，避免显示画面随 ROI 变化而跳动。底部显示当前视频、帧号和播放状态；按 `H` 可以展开详细几何信息。

让识别窗口获得焦点后，使用英文输入法操作：

| 按键 | 操作 |
| --- | --- |
| `N` / 右方向键 | 下一段视频 |
| `P` / 左方向键 | 上一段视频 |
| 空格 | 暂停 / 继续 |
| `R` | 从头重播当前视频 |
| `H` | 简洁 / 详细标记 |
| `Q` / `Esc` / 窗口关闭按钮 | 退出整个程序 |

字母按键不区分大小写。暂停时切换或重播会显示对应视频的第一帧，并保持暂停。`N` 用于切换视频，不是单步下一帧。

开发版的视频模式使用同一套播放按键，并保留阶段查看和插件开关等调试功能；其中 `O` 切换手动 ROI，`R` 用于重播。

每一帧都先完成识别和显示，再读取下一帧，不会为了追赶视频时间而跳帧。计算速度不足时会慢放；计算足够快时，按源视频帧率限制播放速度。`main.py` 中的 `FRAME_HOLD_MS` 可以增加每帧结果的停留时间，默认为 `0`。读取或识别报错时停止在当前视频，窗口保留错误提示，可用 `N` / `P` 切换、`R` 重试或退出。

## 当前算法与代码现状

1. 将输入帧按比例缩小到长边不超过 1280 像素；定位浅色矩形背景板，裁剪有效区域，定位不确定时回退原图。
2. 估计手臂方向并转正，进行肤色分割、掩膜清理和手掌重建。
3. 根据掌心、指尖、指缝、指轴和短凸起轮廓，判断五指身份及伸缩状态。
4. 将识别标记映射回原始画面，显示当前帧结果。

掌宽在掌心至掌后侧测量，减少外展手指对掌宽和指根位置的干扰；拇指判断结合分支基部、掌侧位置和相对长度，改善竖起的拇指被识别成食指的问题。几何判断使用按掌半径归一化的特征，没有按照片编号、文件名或素材批次设置识别分支，也不读取正确答案参与识别。

两版本已同步以下修复：背景板边缘的连通区域需有板内厚度支持，减少空板误报；掌心与颜色种子优先从已定位的背景板内选取，减少板外背景干扰；结合当前帧的掌心 / 背景颜色和分支连接形状，剔除贴在手部轮廓上的阴影；结合独立凸起和指轴关系，改善短拇指漏检及同一手指被重复计数的问题。判断不使用视频名、帧号或参考答案。

根目录仅提供视频输入，省去开发版的插件开关、阶段切换、照片浏览和摄像头入口。固定的软件处理流程仍包含算法内部必要的条件判断及失败回退，并不代表全部运算已经变成硬件流水线。

## 已有验证与局限

截至 2026-10-13，主开发版本在独立照片模式下，按“五根手指的身份和状态全部匹配参考答案”统计：

| 素材组 | 正确数 / 总数 | 开发集准确率 |
| --- | --- | --- |
| 标准开发照片 | 249 / 253 | **98.42%** |
| 其中：最新批次标准照片 | 140 / 141 | **99.29%** |
| 非标准照片 | 21 / 22 | **95.45%** |
| 旧照片回归组 | 25 / 28 | **89.29%** |

这些照片已参与算法开发，且本次没有附在发布仓库中；以上结果不是独立测试准确率，也不是对新人物、新场景或视频的准确率保证。最新标准批次的 141 张来自新增 152 张素材，另外 8 张手背已单独归档、3 张已归入非标准。

本轮修复后，303 张照片没有新增错误，非标准组比修复前多正确 3 张。`test3.mp4` 第 500～600 帧经过逐帧复核：排除 10 个过渡帧后，91 个清晰帧的正确数从 **63 提升到 78（85.71%）**。第 521 帧现在正确识别为“拇指＋食指＋小指”；仍有 **13 个清晰帧错误**，主要涉及小指 / 无名指混淆，也有食指 / 中指混淆。这是参与修复的局部片段结果，不能代表整段视频或新视频的准确率。

开发版与优化版完成 **489 例实现对照**：303 张照片按视频缩放策略输入、18 个抽取视频帧、67 个已确认空板帧，以及上述连续 101 帧。识别测量和简洁 / 详细结果图像全部一致；67 个空板帧均未误报手。实现一致不等于全部识别正确，照片模式的准确率也不能直接当作视频模式准确率。

本次发布还在独立副本、不同工作目录下检查了根目录和 `old/` 两个入口：三视频共 **1651 帧**全部可解码，两版本各完成 **186 个视频帧**的识别与简洁 / 详细绘制对照，结果一致；默认启动、切换视频、暂停、重播及详情切换通过自动检查。验证时使用真实解码、识别和绘制，仅替代窗口与键盘操作，运行不依赖开发工程目录。

同一电脑单线程抽样比较中，20 帧各运行 3 次，平均识别耗时约由 **52 ms/帧增至 58 ms/帧**，不含视频解码和显示。这次修复以减少误判为主，增加了部分运算，不代表所有电脑的运行速度。

三个视频尚未完成全量逐帧标注，**目前没有整段视频准确率数据**。标准照片仍有错误；并拢、遮挡、严重重叠、背手、左手、运动模糊、光照变化和背景板定位失败都可能导致误判。“不可见”与“确认弯曲”也尚未完全区分，非标准素材识别正确不代表恢复了被遮挡手指的完整轮廓。

当前版本是电脑端软件参考，尚未实现 FPGA 硬件逻辑或机械手通信。OpenCV 中的旋转、连通区域、距离变换、轮廓处理等操作，仍需另行设计定点运算、缓存、带宽和硬件流水线。流程简化及软件测试通过，不能保证目标 FPGA 的资源足够，也不能保证实时帧率。

# 右手五指状态识别（OpenCV）

识别右手拇指、食指、中指、无名指、小指的伸开 / 收起状态。当前适用条件是背景变化较小、浅色矩形背景板、右手掌心大致朝向镜头。使用传统图像处理，不依赖深度学习或 MediaPipe。

根目录是当前版本，支持照片、视频和摄像头，已同步至 2026-10-13 的背景板定位、手指识别和显示改进。`end/` 保留此前独立的照片优化版，其算法没有同步本轮修复；查看当前效果请运行根目录 `main.py`。

## 安装与运行

在仓库根目录执行，已验证环境为 Windows / Python 3.11.9。需要带窗口功能的 `opencv-python`，不能只安装 headless 版本。

```powershell
python -m pip install -r requirements.txt

# 默认读取 data/test/test1.mp4，播完循环
python -B main.py
python -B main.py video test1.mp4

# 浏览标准开发照片、非标准照片、历史照片
python -B main.py image new
python -B main.py image nonstd
python -B main.py image old

# 摄像头
python -B main.py camera
```

视频参数接受 `data/test/` 中的文件名或视频绝对路径。照片入口按素材组选择，不接受任意照片路径；把自己的照片放进 `data/new/`，程序会枚举该目录下的常见图片格式。

素材不随 Git 仓库提供。本机 `data/` 是指向开发素材的目录联接，不入 Git；新克隆仓库需要自行创建素材目录并准备照片或视频。运行识别不需要真值表、实验脚本或开发目录的 `codex/`。

## 显示与操作

默认显示原图并叠加识别结果，内部裁板、转正后会把标记映射回原图，避免画面随裁剪区域变化而跳动。照片显示编号、预期手指、识别手指及“正确 / 不正确”；没有参考答案时显示“未标注”。默认精简标记，可按 `h` 展开详细几何信息。

视频逐帧读取、计算、显示结果后才处理下一帧，计算较慢时播放随之变慢。可在 `main.py` 调大 `VIDEO_FRAME_HOLD_MS`，增加每帧结果显示后的停留时间；默认值为 `0`。

请在识别窗口获得焦点后使用英文输入法操作。大小写不同的 `r` 和 `R` 对应不同功能。

| 按键 | 操作 |
| --- | --- |
| `q` / `Esc` | 退出 |
| 空格 | 暂停 / 继续 |
| `n` / `p` | 照片下一张 / 上一张，首尾循环 |
| `n` | 视频暂停后处理下一帧 |
| `R` | 照片重读当前文件和真值表；视频从头重播 |
| `1`～`7` | 切换处理阶段的显示 |
| `6` | 原图叠加识别结果 |
| `7` | 原图上的背景板定位结果 |
| `h` | 简洁 / 详细标记 |
| `b` | 开关自动背景板定位裁剪 |
| `r` | 开关手动 ROI 限制 |
| `m` | 镜像开关 |
| `d` | 信息叠加开关 |
| `f` | 全屏开关 |
| `l` | 在终端列出处理插件 |

内部五指编码顺序为 `T I M R P`：拇指、食指、中指、无名指、小指。界面的五指状态列表按右手观看习惯倒序显示。

照片的可选参考答案放在同目录 `_真值.tsv` 中，每行前两列为文件名和伸出手指编码，以 **Tab** 分隔。编码可为 `TIMRP`、`IP` 等；第二列为空表示握拳，需要保留文件名后的 Tab。`#` 开头的行作为注释。参考答案只在识别结束后用于显示比对，不参与分割、方向估计或手指判断。整理后的素材目录另有 `_编号对照表.tsv`，可追溯旧编号。

## 当前处理流程

1. 根据浅色区域及直线边缘定位矩形背景板，允许手臂遮挡部分板边；定位不确定时回退原图。
2. 裁剪板面有效区域，再估计手臂方向并转正。
3. 进行肤色分割、掩膜清理与手掌重建。
4. 根据掌心、指尖、指缝、指轴和短凸起轮廓，判断五指身份及伸缩状态。
5. 把识别标记映射回原图显示；照片模式另外比对参考答案。

本轮在掌心至掌后侧测量掌宽，减少外展手指对掌宽和指根位置的干扰；同时利用分支基部、掌侧位置和相对长度，改善竖起的拇指被判成食指的问题。判断使用按掌半径归一化的几何特征，没有按照片编号、文件名或批次设置识别分支。掌宽扫描次数不增加，拇指判断复用已有轮廓特征。

## 验证结果与限制

2026-10-13，按“五根手指的身份和状态全部匹配参考答案”统计：

| 分组 | 优化前 | 当前结果 |
| --- | --- | --- |
| 标准开发照片 | 234 / 253，92.49% | **249 / 253，98.42%** |
| 其中：最新批次标准照片 | 125 / 141，88.65% | **140 / 141，99.29%** |
| 非标准照片 | 17 / 22，77.27% | **18 / 22，81.82%** |
| 历史照片对照 | 25 / 28，89.29% | 25 / 28，89.29% |

最新导入的 152 张中，8 张手背单独归档、3 张转入非标准，剩余 141 张计入标准组。标准照片剩余错误为新编号 **0026、0089、0098、0183**，其中 0183 属于最新批次。

以上照片已参与开发，数据是开发集准确率，不能视为独立测试准确率或新人物、新场景的保证。相同的 303 张原图复测没有出现原本正确变错误；标准和非标准共 275 张照片的缩放、平移、旋转等 6 组验证中，正确数由 1431 / 1650 提升到 1550 / 1650，但仍出现 2 个回退：0078 放大 1.25 倍、0241 旋转 +3°。这些扰动仍来自同一批照片，不是独立测试集。视频没有逐帧真值，尚不能报告视频准确率。

非标准照片的状态匹配不代表恢复了被遮挡手指的完整轮廓。当前仍依赖可见特征，“不可见”与“确认弯曲”尚未完全区分；并拢、严重重叠、背手、左手、运动模糊及背景板定位失败可能导致误判。算法也仍有几何阈值和手形先验，需要继续用新素材验证。

## 历史 end 版本

需要对照此前照片优化方案时可运行：

```powershell
python -B end/main.py "data/new"
```

该版本接受照片或文件夹路径，`N` / 右方向键 / 空格下一张，`P` / 左方向键上一张，`Q` / `Esc` 退出。它与根目录版本各自独立，不能用它的结果代替当前版本验证。

## FPGA 迁移

本仓库目前是电脑端软件参考，尚未实现 FPGA 硬件逻辑或机械手通信。板定位、旋转、连通区域、距离变换与轮廓处理需要另行评估缓存、带宽、定点化和流水线方案；Python 验证通过不能保证目标 FPGA 的资源和帧率满足要求。

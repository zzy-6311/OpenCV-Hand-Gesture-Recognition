# 黑背景五指识别：FPGA 核心部署说明

日期：2026-10-22。适用目录：本文件所在的 `fpga_new/`。

**本文件规定把当前 Python 核心移植成硬件时必须保留的算法语义、共享方式和验收要求。它不是可烧录工程，也不是已通过综合的资源报告。**

主入口为 `recognizer.recognize_cropped`；`main.py` 是电脑播放器，不能整份转换成硬件。旧 `fpga/`、`win_end/`、`win_yuan/` 使用不同背景和算法，旧白背景 RTL/HLS 资源结果不适用于本版本。

## 1. 交付状态与来源

本轮采用固定裁剪、原生右侧进手、无整帧距离图的算法路线。掌心由有限候选与背景边界距离估计，指尖厚度/长度从轮廓取得。没有恢复 DT 兜底路线。

本文件中的数值算法对应 Python 参考；RAM 分配、打包、握手及单元复用是供 RTL 实施的明确约定，**不代表这些电路已经存在**。

## 2. 图像、坐标和裁剪合同

- 摄像头上游输出固定 **320×180**、8 位 RGB 分量。Python 接口为 **BGR 排列、uint8、形状 `(180,250,3)`**，不要把 RGB 字节顺序直接接入。
- 固定保留原图 `40 <= x < 290`、`0 <= y < 180`，得到 **250×180**，共 45,000 像素。核心坐标 `x_core=x_input-40`、`y_core=y_input`。
- 扫描顺序：从左上开始，x 先递增，换行后 y 递增。坐标均为像素中心的整数索引。
- 黑背景、右手掌朝镜头、手从图像右侧进入。没有自动找板、动态图像 ROI、旋转或转置。手轴仅用于点的几何投影。
- FPGA 上游已经输出 320×180 时，不再做缩放；电脑原图缩放及把点映射回原图属于 PC 适配/显示部分。
- 不接受其他尺寸后静默填充、拉伸或剪断数据。协议错误必须输出失败状态。

建议输入握手为 `pixel_valid/pixel_ready`、8 位 B/G/R、`frame_start`、`line_end`。在 `valid && ready` 时接受一个像素；`ready=0` 时数据及边界信号保持。若摄像头不能暂停，必须由上游 FIFO/接收帧缓存吸收回压，不能丢点后继续拼成一帧。

## 3. 前景分割：精确整数公式

参考的灰度转换等价于：

```text
S = 3735*B + 19235*G + 9798*R          // unsigned，结果不超过 8,355,840
Y = (S + 16384) >> 15                // 最近取整，正数半值向上；不是 ties-to-even
foreground = (Y >= 40)              // 门槛包含 40
```

当前参考直接按行计算 `foreground = (S >= 1294336)`，没有整帧 gray 中间图。RTL 采用同一个阈值；原来的灰度转换也可像素流式完成，因此不能把软件少一张 gray 图单独计为必然省一块硬件 RAM。常数乘法可由综合器或手写移位加法实现，需核对净面积。

`S+16384` 最大 8,372,224，**23 位无符号**足够；各乘积和累加不得用 16 位容器截断。不能使用有符号 23 位累加器。

本机 OpenCV 5.0.0/NumPy 2.4.6 对全部 16,777,216 种 uint8 BGR 组合验证，上述 Q15 公式与 `cvtColor` 灰度零差异。常见 Q14 系数 `(1868,9617,4899)` 有 43,864 个灰度差异，其中 98 个会改变阈值 40 的掩膜，不能未经验证替换。

## 4. 阶段顺序与必须保持的语义

### 4.1 去噪、入口和连通保留

1. 二值掩膜做 3×3 十字核开运算：先腐蚀、后膨胀。核为 `010/111/010`。
2. 逐列记录连续前景长度，选出曾出现长度至少 12 的最右列。
3. 该列取最长连续段；长度相同时取上方第一段。保存 `entry_x` 和 `entry_y2=start+end-1`，其中 end 是不含末点的结束索引。
4. 入口作为种子，执行 **正扫、反扫、正扫、反扫**四趟 **8 邻接**传播。
5. 清除未与种子相连的前景；保留面积至少 90，否则返回无有效手部前景。

源码在每行以“整个连续段”传播：段内任一点有种子，则整段一次标记。RTL 不能擅自改成只访问左邻居的普通单像素扫描后宣称四趟等价。可用行内段首/段尾记录与回写实现，但需计入额外读取、写回和控制周期。

### 4.2 补洞

将四条图像边上的背景作为种子，执行同样方向顺序的四趟 **4 邻接**传播；每行连续背景段统一标记。最后保留前景及未连到外边界的背景洞。

连通保留与补洞各自只需要三种逻辑状态，但两者含义不同。建议统一编码：`00=待访问/背景`、`01=已访问/种子`、`10=前景/待保留`、`11=保留不用`，由阶段控制解释。Python 用 0、1、255 表示，不要把 255 当硬件需要八位的理由。

固定四趟不是对所有曲折任意形状收敛到完整连通闭包的证明。验证必须对齐当前四趟行为，不能悄悄换成无限迭代后仍引用同一成绩。

### 4.3 掌心临时修整

保留清理后原始二值掩膜 A，工作帧 B 做 **3×3 全 1 方形核**膨胀三遍、腐蚀三遍。每遍独立完成后开始下一遍。

只实例化 **一套可切换膨胀/腐蚀、十字/方形核的 3×3 单元**，开运算和六遍掌心修整共用。不得将六次调用展开成六套窗口电路。

图像外的窗口值与当前 OpenCV 默认形态学语义一致：膨胀用 0，腐蚀用 255（逻辑 1）。不要在腐蚀阶段也补 0。每次遍历要正确刷新行缓存、处理第一/最后行，不跨帧带入状态。

“原地”软件操作不意味着同步 RAM 可以无代价同址读写。用两行历史和窗口寄存器保护尚待使用的旧值，或证明相应反馈调度；不能误读本遍刚写的新像素。

### 4.4 无距离图的掌心定位

1. 每隔 8 列及最后一列（0、8、…、248、249），选该列最长前景段的中点，最多 **33** 个种子；相同段长取上方，中点向下取整。采样列均空时使用第一条存在前景的列作为保底候选。
2. 对工作帧逐行产生背景边界：当前像素为 0，且 3×3 邻域中至少一个像素为前景。**只取图像内背景，不在图像外虚构零边界。**
3. 对每个有效候选累计边界最小距离 `d=4*max(abs(dx),abs(dy))+2*min(abs(dx),abs(dy))`。
4. 选距离最大者；平局按 `(y,x)` 小者优先。以该点为中心，步长 2、步长 1 各做一轮 3×3 九候选细化，保留全局最优。
5. 半径为 `d/4`。无有效候选或无背景边界时不能生成虚构有效掌心；无边界哨兵 2047 不得作为有效半径进入后续窗口/几何计算，按无效掌心拒绝。

三个批次 `33 + 9 + 9` **共用一张候选表和一个距离更新单元**。一个边界点出现后，扫描可暂停，依次更新该批候选，再继续读取；不能照 NumPy 广播写成 33 套并行距离电路。

只保留相邻行/窗口和候选表，不保留整帧 boundary 图、bx/by 边界坐标列表或整帧距离图。硬件可用两行历史（500 位）加当前行像素及 3×3 窗口，以一行延迟形成邻域；还要单列寄存器、计数和同步 RAM 延迟。Python 使用行内暂存验证数值，不代表已完成此硬件映射。两轮细化之间有数据依赖，需要再次遍历工作帧；不是只扫描一次就得到全部结果。

### 4.5 手轴、截臂和轮廓

入口中点为 `(entry_x,entry_y2/2)`，与掌心确定单位手轴；轴不可靠时采用固定向左参考。只投影点，不旋转像素图。

按掌心/半径/手轴截去前臂。截空时保留原始清理掩膜，不能输出空手冒充截臂成功。掌心工作帧 B 到此可复用于截臂输出；A 保留至截空检查结束。

提取最大面积外轮廓，对齐 `RETR_EXTERNAL + CHAIN_APPROX_NONE` 的逐像素 **8 邻接整数轮廓**。允许重复点。稀疏近似轮廓不能直接喂给后续弧长计算。

### 4.6 指尖、精测和五指身份

候选由局部突出度和形状产生；排除手腕侧、掌边与裁剪伪角，再用轮廓双侧测量的长宽排除鼓包。左/上/下边界截断手指采用现有通用截断处理，右侧入口不参与这种恢复。没有读取 DT 或恢复旧肤色/模板兜底。

轮廓相邻步长 Q4 为：重复点 0、横/竖 16、斜向 23。按需计算并累加，不创建逐边长度表。候选带原轮廓编号；重复坐标按首次出现规范化，不引回坐标匹配字典或平方距离最近点后备搜索。

当前 `_sample_tip_side` 已改为顺/逆逐点读取，只保留前后端点和一个 Q4 弧长累计器，边插值边生成固定 61 个采样点；不再生成变长侧轮廓链或局部弧长数组。仍保留两侧固定采样及其后续中点/宽度小数组，不是完全零中间存储。相邻重复点坐标相同，插值必须保留原 `np.interp` 端点和零长度边语义；全链耗尽后补最后一个坐标，不能发生死循环。独立验证 3,054 次完整测量特征和 150 组插值边界与原路径完全一致。

各候选轮流使用一套侧轮廓采样、长宽/方向测量和归一化服务。掌宽、指根投影及 Q6 槽位组合决定 T/I/M/R/P 状态。仍保留短手指救回；已删除闭合指节辅助补齐五指身份的旧支路。

角度排序保留局部坐标的半区判定，区内方向次序用原始整数像素向量叉积比较，不调用 atan2/acos。两个乘积先分别扩位，再相减，保守使用 signed19 保存差值；不能在小位宽乘积相减后才扩位。共线平局按源码稳定次序处理。

下表是固定 250×180 范围可说明的字段；其余浮点参考量不能未经误差试验就生硬截成同一位宽。

| 字段 | 约定/范围 |
| --- | --- |
| 像素 x、y | 各 uint8；实际 x 0…249，y 0…179 |
| 像素地址 | uint16；0…44999 |
| 入口 `entry_x / entry_y2 / valid` | 8 / 9 / 1 位，共 18 位；y2 0…358 |
| 连续段长度 | uint8；0…180，累加前保证不会超过图高 |

| 掌心候选有效性 | 越界或非前景候选写 score=0；有效前景分数大于 0，无须每项额外 valid 位；无边界为 2047 |

| 轮廓弧长 | Q4；单侧最多 2048 个点、2047 条边，最大 47081，用 uint16；不得对整个流程所有和都沿用 16 位 |
| 量化手轴/指轴分量 | Q5 码 -32…32，signed7；这是单位向量分量范围，不适用于所有归一化位置 |
| 指根位置 | Q6；整数范围 -64…128，signed9；槽位参考 45/29/13/3 |
| 指根差平方及总成本 | 先扩位，平方非负；最多四项，上界 4×192²=147456，uint18 足够 |
| 拇指比值比较 | 已界定 Q5 操作数绝对值不超过 1712，signed12；单个乘积 signed23；若相减需 signed24 |

不要把 11 位掌心候选距离误解为仍保留 11 位整帧距离图。旧“距离图从 11 位变 10 位”的备选不与本路线叠加计收益。

`np.rint` 的半值取偶与灰度的正数加半取整不同，RTL 要分别实现。所有乘法、平方、求和在截位前先扩位；未定义的回绕、饱和、除零均禁止。非法/非有限几何应返回拒识，不能制造一个巨大数继续参与排序。

开方、除法、插值和轴归一化仍有浮点数值参考用途。核心已不要求反三角角度计算，但**不是全定点算法**。先实现并验证一套共享数值服务，再对各接口决定定点格式；不得把 Python float64 直接逐句展开成许多双精度单元，也不得未测试就宣称用小整数完全等价。

## 6. 容量限制与输出协议

本轮容量常量：`MAX_CONTOUR_POINTS=2048`、`MAX_RAW_CANDIDATES=16`、`MAX_MEASUREMENT_REQUESTS=44`、`MAX_MEASUREMENT_COMPUTATIONS=22`、`MAX_TIP_SAMPLES=61`，上限均包含该值。原始候选指距离极值及手腕侧排除后、精测前的候选。

缓存为 16 槽，以规范化后的 contour_index 查找；每槽保存一份原始测量及其 tip/center/up/radius 参数标签。同一候选身份判定的量化轴确实不同才覆盖重测。44 次请求预算来自最多 16 次初测、16 次针刺复核、6 次弱帽复核、6 次身份测量；实际计算最多 16 次初测加 6 次量化轴变化重测，即 22 次。缓存 16 槽并不意味着整帧只计算 16 次。缓存与计数每帧新建/清零。部署固定使用 DEFAULT_CONFIG；默认每侧 61 个非负、递增采样位置，不能把可变配置对象直接移植到硬件。RECOG_TIP_MAX_COUNT 必须与 MAX_IDENTIFICATION_TIPS 同为 6，否则要重做 44/22 的上限证明。

Python 捕获 `GeometryCapacityError` 后令 recognition/finger_states 为 None，并写 `flags.geometry_rejected` 与 `flags.capacity_rejected={reason,actual,limit}`。原因包括 `contour_capacity_exceeded`、`raw_candidate_capacity_exceeded`、`measurement_request_capacity_exceeded`、`measurement_candidate_capacity_exceeded`、`measurement_computation_capacity_exceeded`、`tip_sample_capacity_exceeded`。

目前 OpenCV 先生成轮廓再由参考代码检查长度；RTL 必须在追踪第 2049 点时立即中止，不能照搬成先分配无限轮廓再检查。2048×16 位坐标 RAM 为 32768 逻辑位（4 KiB），轮廓 profile/标记/候选特征及接帧空间另计。

超限必须输出 **UNKNOWN/OVERFLOW**，不截断轮廓、不静默丢候选、不返回全零五指冒充握拳。2048 覆盖本批素材，不是任意合法形状的数学上界；容量限制是主动选择的部署边界。

建议硬件结果分开传输 `frame_id`、`status`、`finger_bits`、`reason`。如下为新部署接口约定，尚非已实现 RTL：

- `status=0`：UNKNOWN，存在前景但几何拒识；`status=1`：NO_HAND，清理后无有效前景。
- `status=2`：VALID_HAND，五指位有效；五指全 0 是正确握拳。
- `status=3`：FRAME_ERROR，输入帧格式、容量、超时或接收溢出错误。
- `finger_bits[0..4]=T,I,M,R,P`，仅 `VALID_HAND` 时供应用解释；其他状态置 0，不能因此展示成握拳。
- `reason` 至少区分非法输入、轮廓超限、候选超限、精测超限、无效掌心、几何失败、处理超时、接收溢出。具体数值编码应与最终驱动一并冻结。

Python 结果映射时，先检查容量/输入错误，再检查 recognition；无结果时仅 kept_components=0 可归为 NO_HAND，保留了前景但掌心或几何失败应归为 UNKNOWN。每帧清零状态、候选数量/分数及诊断标记；不能用上一帧正确答案填本帧失败结果。显示所需原图、颜色、文字、指缝及角度只属于 PC，不进入核心面积核算。

## 7. 建议存储布局与打包

**以下是供 RTL 使用的显式位序约定；Python ndarray 本身没有实现此打包。**

- 单平面图像按行连续，`address=y*250+x`；32 位字地址 `address>>5`，字内位 `address&31`，较小像素地址放较低位（LSB-first）。每帧 1407 个字，最后 24 个填充位固定 0；不在每行插入 6 个填充位。
- 三状态图使用两张这样的位平面：A 表状态 bit0，B 表状态 bit1。逐像素操作要读到对应两位，不能把 A/B 当两个独立二值语义同时使用。
- 轮廓点打包 uint16：bits7:0=x、bits15:8=y；若输出字节文件，低字节在前。长度/计数独立保存，不使用 `(0,0)` 作为结束符。
- 多字节外部记录采用 little-endian。若板载总线另有字节顺序，只在适配层转换；核心坐标及指位顺序不变。

| 阶段 | A/B 的使用 | 额外状态 |
| --- | --- | --- |
| 连通保留与补洞 | 两平面共同编码三状态 | 行内段、行历史、计数 |
| 掌心修整 | A 原始二值手；B 修整工作帧 | 3×3 行历史、33 条候选 |
| 截臂与轮廓 | B 变为截臂结果；A 保留到截空检查结束 | 轮廓 RAM、有限候选和精测状态 |

两张二值帧逻辑容量合计 90,000 位（约 10.99 KiB），不是物理 BRAM 数量结论。分组、端口、字宽、读改写和同步 RAM 延迟都会改变映射。对每个状态画读写时序表，再确定单/双端口及能否覆盖旧数据。

## 8. 连续输入、共享与周期预算

摄像头不能暂停时，下一帧接收可能另需一张 45,000 位二值帧/FIFO。能否复用 A/B 要根据实际阶段重叠和端口证明，不能漏算；增加一张缓存只能吸收抖动，不能解决长期处理不过来。

掌心候选为三批，初筛/准备加三次扫描约 180,000 个像素动作；边界点数 B 对应最多 `51×B` 次共享候选更新。保守完全串行模型约 `180000+51B`，B<=45000 时为 2,475,000 个动作。该数不是已测周期，内存等待及调度可能增加周期；读扫描和更新能否重叠也要按端口决定。

六遍掌心修整另有 270,000 个像素位置；清理、补洞、开运算、轮廓和几何还要另计。50 MHz/30 fps 每帧约 1,666,667 拍，100 MHz/30 fps 约 3,333,333 拍。**目前不能保证任意输入在这些预算内完成。**

按 2048 点轮廓及 22 次实际精测上限，每次双侧各最多 2048 次点访问，侧轮廓读取请求最多 90,112 次；这不含其他轮廓统计、重复搜索、插值运算、重读或 RAM 等待，也不是总周期。

本轮 902 帧观测到的最大轮廓为 1043 点、精测请求 17 次、实际精测 6 次，单帧掌心边界点最多 1123、三批候选更新合计最多 52781。这些只是素材观测最大值，不能替代上面的容量/最坏情况预算。

先落实一个共享候选更新单元和一个共享几何服务，测最坏请求量。仅在时序预算证明确有必要时少量增加并行度，不展开 33/51 套或每指一套。超时应返回显式错误并完整重同步下一帧，不跨帧混用缓存。

## 9. RTL 落地顺序和验收

1. 冻结本说明与三份源码 SHA256；用发布视频直接跑 Python，确认环境、BGR 次序和裁剪。
2. 先做灰度阈值、开运算、清理/补洞、六遍修整的逐阶段对拍。每阶段比较完整掩膜，不只比较最终五指。
3. 对拍行式边界生成、每批候选最小距离、平局顺序、两轮细化及最终掌心。不得保存边界全图后漏算其 RAM。
4. 对拍轮廓起点/方向/重复点规则和截臂边缘，再比候选索引、测量特征、Q6 分配成本。若 RTL 使用不同但等价轮廓顺序，需要先证明下游不受影响。
5. 制定各共享数值服务的位宽与舍入，先逐算子误差对拍，再跑照片和视频；每次降低精度独立记录影响。
6. 测边界：纯黑、纯白、四边触碰、上/下截断手指、短入口、曲折噪声、重复轮廓点、容量恰好等于上限及超一、除零、输入中断、连续帧和背压。
7. 重新统计 300 张照片及 87 个明确标注视频帧；按较严格的“正确数相对基线下降不超过 5%”验收，两项分别要求照片至少 280/300、标注视频至少 81/87，也满足下降不超过 5 个百分点。报告新错和修复样本，不能只给同一个总分。其余 815 帧只用于运行/变化检查，不能当有标签准确率。
8. 综合在同一目标器件、时钟、30 fps 输入及相同接口下比较：LUT/FF、BRAM、DSP、最坏周期、吞吐、外部读写和峰值同时缓存。先看减少了哪个实际实例，再讨论总百分比。

Python 播放器逐帧慢放不丢帧，不是连续摄像头吞吐证明。旧白背景综合结果、CPU 毫秒数、Python 数组字节数均不能直接替代此项验收。

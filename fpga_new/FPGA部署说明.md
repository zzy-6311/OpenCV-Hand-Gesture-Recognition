# 黑背景五指识别：FPGA 核心部署说明

日期：2026-10-22，第二轮面积优化。适用目录：本文件所在的 `fpga_new/`。

**本文件规定把当前 Python 核心移植成硬件时必须保留的算法语义、共享方式和验收要求。它不是可烧录工程，也不是已通过综合的资源报告。**

主入口为 `recognizer.recognize_cropped`；`main.py` 是电脑播放器，不能整份转换成硬件。旧 `fpga/`、`win_end/`、`win_yuan/` 使用不同背景和算法，旧白背景 RTL/HLS 资源结果不适用于本版本。

## 1. 交付状态与来源

本轮在上一版无DT核心上继续缩减硬件结构：最大实心正方形逐行定位掌心，有界整数峰谷队列生成候选，双侧同步采样累计特征。撤掉旧掌心候选评分、四组61项数组、三尺度角度/转折检查及不可达针状救回，无旧算法兜底。

Python定义数值行为；下文RAM布局、握手和单元共享规定RTL如何实现，尚不是现成硬件。固定使用DEFAULT_CONFIG，不把可变配置对象综合进核心。

## 2. 图像、坐标和裁剪合同

- 摄像头上游输出固定 **320×180**、8 位 RGB 分量。Python 接口为 **BGR 排列、uint8、形状 `(180,250,3)`**，不要把 RGB 字节顺序直接接入。
- 固定保留原图 `40 <= x < 290`、`0 <= y < 180`，得到 **250×180**，共 45,000 像素。核心坐标 `x_core=x_input-40`、`y_core=y_input`。
- 扫描顺序：从左上开始，x 先递增，换行后 y 递增。坐标均为像素中心的整数索引。
- 黑背景、右手掌朝镜头、手从图像右侧进入。没有自动找板、动态图像 ROI、旋转或转置。手轴仅用于点的几何投影。
- FPGA 上游已经输出 320×180 时，不再做缩放；电脑原图缩放及把点映射回原图属于 PC 适配/显示部分。
- 不接受其他尺寸后静默填充、拉伸或剪断数据。协议错误必须输出失败状态。

建议输入握手为 `pixel_valid/pixel_ready`、8 位 B/G/R、`frame_start`、`line_end`。在 `valid && ready` 时接受一个像素；`ready=0` 时数据及边界信号保持。若摄像头不能暂停，必须由上游 FIFO/接收帧缓存吸收回压，不能丢点后继续拼成一帧。

## 3. 前景分割：精确整数公式

参考的灰度转换等价于：

```text
S = 3735*B + 19235*G + 9798*R          // unsigned，结果不超过 8,355,840
Y = (S + 16384) >> 15                // 最近取整，正数半值向上；不是 ties-to-even
foreground = (Y >= 40)              // 门槛包含 40
```

当前参考直接按行计算 `foreground = (S >= 1294336)`，没有整帧 gray 中间图。RTL 采用同一个阈值；原来的灰度转换也可像素流式完成，因此不能把软件少一张 gray 图单独计为必然省一块硬件 RAM。常数乘法可由综合器或手写移位加法实现，需核对净面积。

`S+16384` 最大 8,372,224，**23 位无符号**足够；各乘积和累加不得用 16 位容器截断。不能使用有符号 23 位累加器。

本机 OpenCV 5.0.0/NumPy 2.4.6 对全部 16,777,216 种 uint8 BGR 组合验证，上述 Q15 公式与 `cvtColor` 灰度零差异。常见 Q14 系数 `(1868,9617,4899)` 有 43,864 个灰度差异，其中 98 个会改变阈值 40 的掩膜，不能未经验证替换。

## 4. 阶段顺序与必须保持的语义

### 4.1 去噪、入口和连通保留

1. 二值掩膜做 3×3 十字核开运算：先腐蚀、后膨胀。核为 `010/111/010`。
2. 逐列记录连续前景长度，选出曾出现长度至少 12 的最右列。
3. 该列取最长连续段；长度相同时取上方第一段。保存 `entry_x` 和 `entry_y2=start+end-1`，其中 end 是不含末点的结束索引。
4. 入口作为种子，执行 **正扫、反扫、正扫、反扫**四趟 **8 邻接**传播。
5. 清除未与种子相连的前景；保留面积至少 90，否则返回无有效手部前景。

源码在每行以“整个连续段”传播：段内任一点有种子，则整段一次标记。RTL 不能擅自改成只访问左邻居的普通单像素扫描后宣称四趟等价。可用行内段首/段尾记录与回写实现，但需计入额外读取、写回和控制周期。

### 4.2 补洞

将四条图像边上的背景作为种子，执行同样方向顺序的四趟 **4 邻接**传播；每行连续背景段统一标记。最后保留前景及未连到外边界的背景洞。

连通保留与补洞各自只需要三种逻辑状态，但两者含义不同。建议统一编码：`00=待访问/背景`、`01=已访问/种子`、`10=前景/待保留`、`11=保留不用`，由阶段控制解释。Python用0、1、255表示，分别映射00、01、10，不需八位状态。连通阶段结束将01转为10（保留前景），00/10转为00；补洞将图像边缘的00背景设为01，传播后01输出二值0，00或10输出二值1。注意：01在连通阶段是已访问的前景，在补洞阶段是外部可达背景，必须在阶段交界转换，不能混用语义。

固定四趟不是对所有曲折任意形状收敛到完整连通闭包的证明。验证必须对齐当前四趟行为，不能悄悄换成无限迭代后仍引用同一成绩。

### 4.3 掌心临时修整

保留清理后原始二值掩膜 A，工作帧 B 做 **3×3 全 1 方形核**膨胀三遍、腐蚀三遍。每遍独立完成后开始下一遍。

只实例化 **一套可切换膨胀/腐蚀、十字/方形核的 3×3 单元**，开运算和六遍掌心修整共用。不得将六次调用展开成六套窗口电路。

图像外的窗口值与当前 OpenCV 默认形态学语义一致：膨胀用 0，腐蚀用 255（逻辑 1）。不要在腐蚀阶段也补 0。每次遍历要正确刷新行缓存、处理第一/最后行，不跨帧带入状态。

“原地”软件操作不意味着同步 RAM 可以无代价同址读写。用两行历史和窗口寄存器保护尚待使用的旧值，或证明相应反馈调度；不能误读本遍刚写的新像素。

### 4.4 单行状态的最大实心正方形掌心

修整图为空或全前景时拒识，不制造掌心。逐像素维护能以当前像素为右下角的最大实心正方形边长S：

```text
old_up = row[x]
S = foreground ? min(old_up, old_up_left, left) + 1 : 0
row[x] = S
old_up_left = old_up
left = S
```

每行开始left=old_up_left=0，整帧开始row清零。只需250项uint8行状态；图外不能延长正方形。同步RAM必须先读旧值再覆盖，显式处理读延迟和left依赖。**不可将NumPy的`minimum.accumulate`展开成250套更新单元，也不可把宿主行临时数组逐一映射成额外RAM。**

记录最大边长；中心为`(x-(S-1)//2, y-(S-1)//2)`，偶数边长取中间四点中的右下点。最大边长相同则选择中心`(y,x)`字典序最小者。半径Q1码`R2=(45*S)//32`，R=R2/2；45/32近似√2。S≤180，R2≤253、R≤126.5；R<8拒识。这是掌区尺度估计，不表示该圆内全部为前景。

45×S最大8100，13位无符号中间值；用移位加法实现常数乘。旧33＋9＋9候选、Q2最小边界距离、2047哨兵、边界扫描与两轮局部细化已全部删除。

新行状态2000位，旧候选957位＋边界历史500位为1457位，局部净增543位，换取简单取小/加一及单遍定位。若2000位被迫独占大BRAM，物理块数可能增加；需检查小RAM映射或可复用存储，不能将此项写成“必然省RAM”。

### 4.5 手轴、截臂和轮廓

入口中点为 `(entry_x,entry_y2/2)`，与掌心确定单位手轴；轴不可靠时采用固定向左参考。只投影点，不旋转像素图。

按掌心/半径/手轴截去前臂。截空时保留原始清理掩膜，不能输出空手冒充截臂成功。掌心工作帧 B 到此可复用于截臂输出；A 保留至截空检查结束。

提取最大面积外轮廓，对齐 `RETR_EXTERNAL + CHAIN_APPROX_NONE` 的逐像素 **8 邻接整数轮廓**。允许重复点。稀疏近似轮廓不能直接喂给后续弧长计算。

### 4.6 有界峰谷候选

每轮廓点至整数掌心的距离平方d²≤249²+179²=94042，用uint17；差值先扩为signed9再平方。径向门槛使用平方比较，局部峰谷由两条单调队列维护。窗口半宽`w=max(2,round(0.45*R))≤57`，每队列≤2w+1≤115项，每项12位扫描序号＋17位平方距离，载荷共6670位，另计指针/占用/控制。

循环scan从0至N+2w-1，入队轮廓点`(scan-w) mod N`，输出中心`scan-2w`，恰好输出N个中心，窗口覆盖中心±w。先删过期元素，再依序弹尾、入队；相同值保留后进入者。队列弹尾逐次复用比较器，不能展开115个并行比较路径。

轮廓和队列循环地址使用计数器＋比较回绕，不把变量`%`映射成除法器。每步新入队点、输出中心点需要读取轮廓，双口或分时完成；平方单元共享。没有全长距离、极大值、极小值和局部投影数组。

排除手腕侧后，突出度仍是`sqrt(d²中心)-sqrt(d²谷底) >= 0.2R`，不能换成平方差。窗口round必须半数取偶；Q1半径下用`9*R2/40`的商余数确定舍入。原始候选保留顺序，超过16即拒识，报告首次溢出actual=17。

逐点投影与旧NumPy批量矩阵乘在恰好0.15半平面门槛可能有末位浮点舍入差异，存在合成反例。本轮以逐点结果为新数值参考，不宣称任意输入逐位等价；RTL统一定点门槛后单独验收，不恢复大数组来模仿BLAS末位。

### 4.7 同步采样、固有特征与身份

掌心定位和径向候选使用Q1半径；进入`finger_geometry`的测量及掌宽计算时，半径仍按原规则量化到1像素（半数取偶）。不能把Q1直接一路传到所有后端计算，也不能改成简单截断。

三尺度转折/角度检查及不可达针状救回已删除；专用轴宽变化比值、极值统计和缓存字段也删除。弱候选提升、横向拇指及左/上/下裁边补救保留，右侧入口不参与裁边恢复。长宽和指根证据继续区分伸指与鼓包。

相邻轮廓弧长Q4：重复点0、横/竖16、斜向23。候选带首次出现规范化后的轮廓索引；没有坐标查找字典、最近点后备或逐边长度表。

`_iter_tip_side`顺/逆读取点并插值；`_stream_tip_shape`同步消费两侧当前样本。只保留7项宽度中位数窗、回归统计和、前后端点及游标。默认每侧最多61个位置；完整宽度窗口在首个允许指根之前完成，指根出现且方向窗口完成即可停。链耗尽重复最后一点；零长度边只推进游标，不除以零、不死循环。

左右61点、中点61点、宽度61项四组数组已删除。按8位x/y和11位归一化宽度，旧载荷约3599位；新7项宽度77位、统计91位，另计游标/端点/控制。不能把3599位当最终净节省或直接换算BRAM块数。

方向回归用整数充分统计重建原系数，保留半数取偶的奇偶校正。默认指轴回归窗口为10或11点，宽度中位数窗口为7项；自定义配置必须重新证明位宽。独立验证3054请求剩余特征逐字段一致，420插值、210特征、2000舍入案例通过。

16条缓存只保存点、指根、宽度、长度、轴、轴原点等固有特征，不存随掌心/手轴变化的投影副本；轮廓复用原整数坐标，不复制浮点轮廓。半径、配置、轮廓变化须失效，换帧全部清空。重新判断身份只投影固有特征，不重走轮廓。当前387样本实际完整测量1299→1299，不能宣称缓存实测减少了测量次数。

掌宽三条截线、指根投影和Q6槽位决定五指。沿用原半区/叉积排序及平局稳定次序，无atan2/acos；乘积先扩位。所有候选共用一套采样、回归、开方除法和投影服务，不为每指复制完整电路。

没有整帧距离图或旧11位候选距离表。归一化Q5不表示所有量都只用5位；位置整数部分、符号位和累加位须另算。回归上界取固定250×180及DEFAULT_CONFIG的理论范围，不取素材最大值。

`np.rint` 的半值取偶与灰度的正数加半取整不同，RTL 要分别实现。所有乘法、平方、求和在截位前先扩位；未定义的回绕、饱和、除零均禁止。非法/非有限几何应返回拒识，不能制造一个巨大数继续参与排序。

开方、除法、插值和轴归一化仍有浮点数值参考用途。核心已不要求反三角角度计算，但**不是全定点算法**。先实现并验证一套共享数值服务，再对各接口决定定点格式；不得把 Python float64 直接逐句展开成许多双精度单元，也不得未测试就宣称用小整数完全等价。

## 6. 容量限制与输出协议

本轮包含式容量：`MAX_CONTOUR_POINTS=2048`、`MAX_RAW_CANDIDATES=16`、`MAX_MEASUREMENT_REQUESTS=28`、`MAX_MEASUREMENT_COMPUTATIONS=16`、`MAX_TIP_SAMPLES=61`、`MAX_WIDTH_SAMPLES=7`、`MAX_IDENTIFICATION_TIPS=6`、`RADIAL_MAX_HALF_WINDOW=57`。

请求28次由16初测＋6弱候选复核＋6身份投影组成。缓存按规范化contour_index保存16条固有特征，以tip、量化radius和配置校验有效性，不以center/up作为重测条件。默认配置下完整测量最多16次，投影也计入请求次数。自定义半径或配置反复变化不能绕过16次硬上限。每帧计数与缓存重建，超限返回不可用。

RECOG_TIP_MAX_COUNT和MAX_IDENTIFICATION_TIPS均为6；修改候选、采样范围、步长、半径上限后，需一起重做容量/位宽证明。61是最大位置数，不是61套硬件或固定必须保存的样本数组。

Python 捕获 `GeometryCapacityError` 后令 recognition/finger_states 为 None，并写 `flags.geometry_rejected` 与 `flags.capacity_rejected={reason,actual,limit}`。原因包括 `contour_capacity_exceeded`、`raw_candidate_capacity_exceeded`、`measurement_request_capacity_exceeded`、`measurement_candidate_capacity_exceeded`、`measurement_computation_capacity_exceeded`、`tip_sample_capacity_exceeded`、`width_sample_capacity_exceeded`、`radial_window_capacity_exceeded`。

目前 OpenCV 先生成轮廓再由参考代码检查长度；RTL 必须在追踪第 2049 点时立即中止，不能照搬成先分配无限轮廓再检查。2048×16 位坐标 RAM 为 32768 逻辑位（4 KiB），峰谷队列/候选特征及接帧空间另计。

超限必须输出 **UNKNOWN/OVERFLOW**，不截断轮廓、不静默丢候选、不返回全零五指冒充握拳。2048 覆盖本批素材，不是任意合法形状的数学上界；容量限制是主动选择的部署边界。

建议硬件结果分开传输 `frame_id`、`status`、`finger_bits`、`reason`。如下为新部署接口约定，尚非已实现 RTL：

- `status=0`：UNKNOWN，存在前景但几何拒识；`status=1`：NO_HAND，清理后无有效前景。
- `status=2`：VALID_HAND，五指位有效；五指全 0 是正确握拳。
- `status=3`：FRAME_ERROR，输入帧格式、容量、超时或接收溢出错误。
- `finger_bits[0..4]=T,I,M,R,P`，仅 `VALID_HAND` 时供应用解释；其他状态置 0，不能因此展示成握拳。
- `reason` 至少区分非法输入、轮廓超限、候选超限、精测超限、无效掌心、几何失败、处理超时、接收溢出。具体数值编码应与最终驱动一并冻结。

Python 结果映射时，先检查容量/输入错误，再检查 recognition；无结果时仅 kept_components=0 可归为 NO_HAND，保留了前景但掌心或几何失败应归为 UNKNOWN。每帧清零状态、候选数量/分数及诊断标记；不能用上一帧正确答案填本帧失败结果。显示所需原图、颜色、文字、指缝及角度只属于 PC，不进入核心面积核算。

## 7. 建议存储布局与打包

**以下是供 RTL 使用的显式位序约定；Python ndarray 本身没有实现此打包。**

- 单平面图像按行连续，`address=y*250+x`；32 位字地址 `address>>5`，字内位 `address&31`，较小像素地址放较低位（LSB-first）。每帧 1407 个字，最后 24 个填充位固定 0；不在每行插入 6 个填充位。
- 三状态图使用两张这样的位平面：A 表状态 bit0，B 表状态 bit1。逐像素操作要读到对应两位，不能把 A/B 当两个独立二值语义同时使用。
- 轮廓点打包 uint16：bits7:0=x、bits15:8=y；若输出字节文件，低字节在前。长度/计数独立保存，不使用 `(0,0)` 作为结束符。
- 多字节外部记录采用 little-endian。若板载总线另有字节顺序，只在适配层转换；核心坐标及指位顺序不变。

| 阶段 | A/B 的使用 | 额外状态 |
| --- | --- | --- |
| 连通保留与补洞 | 两平面共同编码三状态 | 行内段、行历史、计数 |
| 掌心修整/定位 | A 原始二值手；B 修整工作帧 | 共享3×3行历史；定位时250×8 DP行状态 |
| 截臂与轮廓 | B 变为截臂结果；A 保留到截空检查结束 | 轮廓RAM、两条115项队列、16条固有特征和共享精测状态 |

两张二值帧逻辑容量合计 90,000 位（约 10.99 KiB），不是物理 BRAM 数量结论。分组、端口、字宽、读改写和同步 RAM 延迟都会改变映射。对每个状态画读写时序表，再确定单/双端口及能否覆盖旧数据。

## 8. 连续输入、共享与周期预算

摄像头不能暂停时，下一帧接收可能另需45000位二值帧/FIFO。能否复用A/B须证明阶段重叠与端口；增加缓冲只能吸收抖动，不能解决长期处理不过来。

六遍掌心修整共270000个像素位置；新DP定位45000个位置，加空/全前景统计与边界控制。空/全前景计数可与修整最后一遍合并，但必须保留一致的拒识行为。旧`180000+51B`候选评分模型已不适用。

径向基础轮廓读取最多`2N+2w=4210`次，不含后续精测。队列入队/弹尾按摊还线性执行，但单点可能多次弹尾；要允许停顿、串行复用比较器和RAM端口，不能按一像素恒一拍承诺吞吐。

16次完整测量、每次双侧各最多2048点，保守点读取预算65536次；不含轮廓追踪、首次出现规范化扫描、掌宽截线、插值重读、算术及RAM等待。早停减少平均周期，不据此减少仍需保留的完整测量单元。

902帧观测最大：轮廓1067点、请求17次、完整测量6次、缓存6条。观测最大不能代替2048/28/16的容量边界。50MHz/30fps每帧约1666667拍，100MHz/30fps约3333333拍；需将清理、补洞、开运算、轮廓和数值服务全部加入最坏周期再评估。

面积优先采用一套形态学窗口、一个DP更新通路、一套共享测量/算术服务。只有吞吐预算证明必要才增加并行度。不要把Python广播、生成器、候选循环或采样循环完全展开。超时输出错误并从下一完整帧重新同步，不跨帧混用数据。

局部内存账目：DP行2000位（比旧局部增加543位），峰谷队列6670位，轮廓32768位，双掩膜90000位，另计窗口、回归、缓存、控制和接帧空间。它们的峰值共存、端口和映射决定物理RAM数；不能简单相加当整板占用，也不能重复核算上一轮已删除的DT收益。
